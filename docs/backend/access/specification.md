# Сервис доступа — спецификация модели данных

Согласованная схема для первого этапа реализации. Общие требования к сервису описаны в [спецификации проекта](../../specification.md#аккаунты-и-роли), термины собраны в [глоссарии](../../../GLOSSARY.md).

## Аккаунты и роли

Первого администратора создаёт скрипт. После входа администратор создаёт остальные аккаунты через защищённый API в Swagger, включая аккаунты других администраторов.

У каждого аккаунта один логин и одна роль. Ученики решают задачи без аккаунта. Для управления аккаунтом предусмотрены создание и смена роли. Созданный аккаунт остаётся действующим.

Миграция заполняет справочник ролей. Администратор получает готовый список через `GET /roles`. Создание аккаунта и смена роли принимают числовой `role_id`. Внутри сервис проверяет права по коду роли.

| Код | Название |
|---|---|
| `admin` | Администратор |
| `author` | Составитель заданий |
| `representative` | Представитель |
| `reviewer` | Проверяющий |

## Логин и пароль

| Поле | Правила |
|---|---|
| Логин | При создании аккаунта и входе убираем пробелы по краям и приводим логин к нижнему регистру. После этого он должен содержать от 3 до 32 символов. Допустимы латинские буквы, цифры, точка, дефис и подчёркивание. Первый символ — буква или цифра. Нормализованный логин уникален. Например, ` Ivanov ` и `ivanov` относятся к одному аккаунту. |
| Пароль | При создании аккаунта требуется минимум 8 символов. Длина в UTF-8 ограничена 72 байтами, чтобы bcrypt мог проверить пароль целиком. Разрешены пробелы и кириллица. Пароль сохраняем в виде хеша и проверяем в том виде, в каком его ввели. [Ограничение bcrypt](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#input-limits-of-bcrypt) |

Правила создания логина и пароля одинаковы для скрипта первого администратора и API.

## Сессии

Каждый успешный вход создаёт отдельную сессию на семь дней. Сервис выдаёт случайный токен и хранит его хеш. Выход отзывает текущую сессию. Например, после выхода с телефона сессия на компьютере продолжает действовать.

При каждой проверке доступа сервис читает текущую роль аккаунта. Смена роли применяется со следующей проверки, в том числе для сессий, выданных раньше.

## Схема PostgreSQL

Все таблицы находятся в базе `access`. Аккаунт ссылается на одну роль, роль может быть назначена нескольким аккаунтам. У аккаунта может быть несколько сессий.

### `roles` — справочник ролей

| Поле | Тип | Назначение и ограничения |
|---|---|---|
| `id` | `smallint` | Первичный ключ. |
| `code` | `text` | Уникальный обязательный код для проверки доступа. |
| `name` | `text` | Обязательное отображаемое название роли. |

### `accounts` — аккаунты

| Поле | Тип | Назначение и ограничения |
|---|---|---|
| `id` | `uuid` | Первичный ключ. |
| `login` | `varchar(32)` | Обязательный уникальный логин в нормализованном виде. |
| `password_hash` | `text` | Обязательный хеш пароля. |
| `role_id` | `smallint` | Обязательный внешний ключ на `roles.id`. |
| `created_at`, `updated_at` | `timestamptz` | Обязательные отметки создания и последнего изменения аккаунта. |

### `sessions` — сессии входа

| Поле | Тип | Назначение и ограничения |
|---|---|---|
| `id` | `uuid` | Первичный ключ. |
| `account_id` | `uuid` | Обязательный внешний ключ на `accounts.id`. |
| `token_hash` | `bytea` | Обязательный уникальный хеш выданного токена. |
| `created_at` | `timestamptz` | Обязательное время создания сессии. |
| `expires_at` | `timestamptz` | Обязательное время окончания. При входе рассчитывается как `created_at` плюс семь дней. |
| `revoked_at` | `timestamptz` | Время отзыва. До отзыва поле пустое. |
